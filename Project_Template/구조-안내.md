# 저장소 구조 안내

이 폴더를 통째로 복사해 **자기 git 저장소의 루트**로 쓰세요. 이 저장소는 **매일 업데이트하는 개발 기록**입니다. **개발 일지(날짜 인덱스)**가 중심이고, README가 그 요약 허브입니다. main은 **브랜치 + PR**로 관리합니다.

## 폴더 구조

```text
<저장소 루트>/
├─ README.md          # 허브: 주제 + 개발 기록(날짜 표, 매일 추가) + 바로가기
├─ .gitignore
├─ .github/
│  └─ pull_request_template.md   # PR 본문 템플릿(What/Why/How/테스트/셀프리뷰)
├─ assets/            # 이미지·gif (README에서 불러옴)
│  └─ README.md
├─ docs/
│  ├─ 개발일지.md       # ★ 날짜 인덱스(중심). 날짜마다 한 일 + 작성한 문서(유형+링크)
│  ├─ 규격/            # ★ 문서를 '어떻게 쓰는가' 규격 + 오늘 뭘 쓸지 선택 가이드
│  │  ├─ README.md     #   규격 목록 + 선택 가이드
│  │  ├─ TIL.md        #   TIL(개념 정리) 작성 규격
│  │  ├─ 설명.md        #   설명 작성 규격
│  │  └─ 어려웠던점.md   #   어려웠던 점 작성 규격
│  ├─ <날짜·주제 폴더>/  # 실제 작성한 문서 인스턴스(규격을 채운 결과)
│  ├─ self-comment.md  # PR별 셀프 리뷰·회고
│  └─ pr-log.md        # PR 작업 내역
└─ src/               # 소스 코드
   └─ README.md
```

## 어떻게 연결되나요 (매일의 흐름)

1. **개발 일지**에 오늘 한 덩어리를 **맨 위에** 추가합니다(한 일 + 그날 쓴 문서 링크).
2. 그날 쓸 문서는 [docs/규격/](./docs/규격/README.md)의 **선택 가이드**로 고릅니다(현재 TIL · 설명 · 어려웠던 점).
3. 고른 규격의 형식대로 문서를 써서 **날짜·주제 폴더**에 두고, 개발 일지에서 링크합니다.
4. README의 **개발 기록** 표와 `docs/pr-log.md`에 한 줄씩 더해 PR로 올립니다.
5. 이미지·gif는 `assets/`에 넣고 `![설명](assets/파일명)`으로 불러오세요.

## git 작업 방식 (브랜치 + PR)

main에 직접 커밋하지 마세요. 작업마다 브랜치를 만들고 PR로 병합하세요.

```bash
# 1) 작업 브랜치 생성
git switch -c feature/<작업이름>

# 2) 작업 → 커밋 → 푸시
git add .
git commit -m "feat: <작업 내용>"
git push -u origin feature/<작업이름>

# 3) GitHub에서 PR 열기 (base: main ← compare: feature/<작업이름>)
#    - 본문은 .github/pull_request_template.md 가 자동으로 채워 줍니다
#    - 내 PR의 변경된 줄에 셀프 코멘트 [nit/question/blocker] 를 남기세요

# 4) 병합(Merge) 후 브랜치 삭제
#    - docs/pr-log.md 와 README의 PR 표를 갱신하세요
```

**브랜치 이름**: `feature/<작업>`, `fix/<버그>`, `docs/<문서>`

**main 보호(선택)**: GitHub 저장소 Settings → Branches → "Require a pull request before merging"을 켜면 main에 직접 푸시가 막힙니다.

## PR 내역을 README로 강조하기

PR을 병합할 때마다 아래 둘을 같이 갱신하세요.

- `docs/pr-log.md`에 PR 한 덩어리 추가(What/Why/How/테스트/셀프 코멘트/상태).
- README "개발 흐름" 표에 한 줄 추가(PR 링크·작업·브랜치·셀프 코멘트 건수·상태).

이렇게 하면 README만 봐도 **무슨 작업을 어떤 PR로 했는지** 한눈에 보입니다.

## 저장소 폴더 이름 추천

git 저장소 이름은 **영문 소문자 + 하이픈**으로 지으세요. 한글·공백·`@` 같은 특수문자는 쓰지 마세요.

- 패턴: `<기술>-<프로젝트>` 또는 `<프로젝트>-<주차>`
- 예시: `csharp-turn-battle`, `turnbattle-minigame`, `cs-week1-turnbattle`
- 개인 구분이 필요하면 뒤에 이름을 붙이세요: `turnbattle-hong`
- 피하세요: `프로젝트`, `새 폴더`, `test`, 한글·공백·`@` 가 들어간 이름

## 처음 올리기

```bash
cd <저장소 루트>
git init
git add .
git commit -m "chore: 저장소 구조 + README"
git branch -M main
git remote add origin <본인 원격 저장소 URL>
git push -u origin main
```

- `.gitignore`가 `bin/`·`obj/`를 제외하는지 확인하세요.
- 빈 폴더는 git이 추적하지 않습니다. `assets/`·`src/`의 `README.md`를 지우지 마세요.
