# 문서 작성 규격

각 문서를 **어떻게 쓰는가**의 기준입니다. 실제로 쓴 문서(인스턴스)는 날짜·주제 폴더에 두고, 형식은 여기를 따르세요.

## 오늘 어떤 문서를 쓸까? (선택 가이드)

| 오늘 한 일이 이렇다면 | 쓸 문서 | 규격 |
|---|---|---|
| 하루 작업을 날짜로 남긴다 (매일·필수) | 개발 일지 | [개발일지](../개발일지.md) |
| 새 개념을 이해했다 (쓸 코드는 아직 없음) | TIL · 개념정리 | [TIL](./TIL.md) |
| 기능을 구현해 구조·동작 설명이 필요하다 | 설명 | [설명](./설명.md) |
| 버그·막힘을 겪고 해결했다 | 어려웠던 점 | [어려웠던점](./어려웠던점.md) |

> 지금 선택지는 **TIL · 설명 · 어려웠던 점**입니다. 과정이 깊어지면 MRE(버그 리포트)·ADR(의사결정)·리팩토링·프로파일링 규격을 이 폴더에 추가합니다.

## 공통 규칙

- 날마다 **개발 일지**에 한 덩어리를 남기고, 그날 쓴 문서를 링크하세요.
- 남이 읽고 **재현**할 수 있게 쓰세요(환경·입력·결과를 남김).
- 문서는 과제가 아니라 **다음의 나에게 남기는 기록**입니다.
