## 1. 정수 나눗셈이 소수점을 버린다

- 증상: `02b-연산자.cs`에서 `10 / 3`을 출력했더니 `3.333…`이 아니라 `3`이 나옴.
- 원인: 두 피연산자가 모두 `int`라 **정수 나눗셈(몫만 계산)** 이 됨. 소수점 이하가 절삭됨.
- 해결: 한쪽을 실수로 만들면 실수 나눗셈이 됨 — `10.0 / 3`, 또는 변수라면 `(double)a / b`.
- 재발 방지: 나눗셈 전에 "두 값의 타입이 무엇인가"를 먼저 확인. 평균·비율처럼 소수가 필요한 계산은 `double`로 받는다.

## 2. ReadLine 입력을 바로 Parse하면 멈춘다

- 증상: `02-실습1-개인정보.cs`에서 나이에 `abc`를 입력하자 `int.Parse(...)`에서 `FormatException`으로 프로그램이 종료됨.
- 원인: `Console.ReadLine()`은 항상 **string**을 돌려주는데, 숫자가 아닌 문자열을 `int.Parse`에 넘기면 예외가 남.
- 해결: `int.TryParse(input, out int age)`로 바꿔, 변환 성공/실패를 bool로 받고 실패 시 안내 메시지를 출력하도록 분기.
- 재발 방지: 사용자 입력은 항상 실패를 전제로 `TryParse`로 받는다. `Parse`는 입력이 신뢰될 때만 쓴다.

## 3. 실수 비교가 기대와 다르다

- 증상: `0.1 + 0.2 == 0.3`을 출력했더니 `False`가 나옴.
- 원인: `double`은 2진 부동소수점이라 일부 10진 소수를 정확히 표현하지 못함. `0.1 + 0.2`가 `0.30000000000000004`가 됨.
- 해결: 실수는 `==`로 직접 비교하지 않고, 오차 범위를 둔다 — `Math.Abs(a - b) < 1e-9`.
- 재발 방지: 정확한 10진 계산(금액 등)이 필요하면 `decimal`을 쓴다. 실수 비교는 허용 오차로 판단한다.
