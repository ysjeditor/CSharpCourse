## 📖 배운 내용
### 1. 값타입과 참조타입의 차이점
- **핵심 원리**: 구조체(`struct`)를 복사하면 값타입 필드(`score`)는 독립적으로 복제되지만, 참조타입 필드(`myBag`)는 **힙(Heap) 메모리 주소만 복사**되므로 원본과 복사본이 같은 객체를 공유한다.

```csharp
class Bag
{
    public bool myBag;
}

struct PlayerInfo
{
    public int score;
    public Bag myBag;
}

class Enemy
{
    int score;
    int damage;
}

static void Main(string[] args)
{
    PlayerInfo playerInfo = new PlayerInfo();
    playerInfo.score = 10;
    playerInfo.myBag = new Bag { myBag = true };

    PlayerInfo copy = playerInfo;
    copy.score = 100;
    copy.myBag.myBag = false;

    Console.WriteLine(\$"플레이어인포 스코어 : {playerInfo.score}");     // 10 (원본 유지)
    Console.WriteLine(\$"플레이어인포 마이백 : {playerInfo.myBag.myBag}"); // False (공유되어 함께 변경)
    Console.WriteLine(\$"카피 스코어 : {copy.score}");                   // 100
    Console.WriteLine(\$"카피 마이백 : {copy.myBag.myBag}");             // False
}
```

### 2. ref의 작동 원리 (함수 스택 주소와 디버깅 분석)
- **일반 매개변수 전달 시 동작 과정**:
  1. 함수가 실행될 때 해당 함수만의 **새로운 스택 공간(스택 프레임)**이 생성된다.
  2. 이때 원본 인자(`playerInfo`) 자체가 실행되는 것이 아니라, **원본이 참조하고 있는 곳의 주소값을 복사해서 새로운 스택 공간의 매개변수(`hp`)에 담아** 실행한다.
  3. 함수 내부에서 `hp = new PlayerInfo()`를 실행하고 디버거를 찍어보면 실제로 값이 `-1000`으로 변하는 것이 보인다.
  4. **핵심 원인**: 원본(`playerInfo`)의 주소값이 수정되었다가 사라지는 것이 아니라, **원본 주소는 처음부터 단 한 번도 수정된 적이 없다.** 단지 `new`를 통해 힙(Heap)에 **새로 만들어진 객체**의 주소를 함수 내 복사본 지역변수(`hp`)가 가리키게 된 것뿐이며, 함수가 종료되면 지역변수(`hp`)와 함께 스택 공간이 소멸하면서 새로 생성된 객체와의 연결도 사라진다.
- **`ref` 매개변수 전달 시 동작 과정**:
  - 새로운 복사본 스택 공간을 만들어 실행하는 것이 아니라, **호출한 쪽 원본 변수(`playerInfo`)의 기존 스택 주소를 직접 가리킨 상태**에서 함수 바디(`{ }`) 안의 내용을 실행한다.
  - 따라서 함수 내부에서 `new PlayerInfo()`를 통해 새 객체를 대입해도 **원본 변수(`playerInfo`)가 가진 참조 주소 자체가 새 객체로 덮어씌워지므로**, 함수가 끝난 뒤에도 변경된 정보가 그대로 유지된다.

```csharp
public class PlayerInfo
{
    public int hp;
    public int mp;
}

internal class ref실습
{
    static void PrintHp(PlayerInfo hp)
    {
        hp.hp = -20;
        hp = new PlayerInfo();
        hp.hp = -1000;
    }

    static void PrintHpRef(ref PlayerInfo hp)
    {
        hp.hp = -20;
        hp = new PlayerInfo();
        hp.hp = -1000;
    }

    static void PrintMp(PlayerInfo mp)
    {
        mp.mp = -20;
        mp = new PlayerInfo();
        mp.mp = -1000;
    }

    static void PrintMpRef(ref PlayerInfo mp)
    {
        mp.mp = -20;
        mp = new PlayerInfo();
        mp.mp = -1000;
    }

    static void Main(string[] args)
    {
        PlayerInfo playerInfo = new PlayerInfo { hp = 1000 };
        playerInfo.mp = 500;

        PrintHp(playerInfo);
        Console.WriteLine(\$"ref 없이 HP : {playerInfo.hp}");         // -20 (기존 객체 값만 수정됨)

        PrintHpRef(ref playerInfo);
        Console.WriteLine(\$"ref 적용 후 HP ref : {playerInfo.hp}");  // -1000 (새 객체로 교체됨)

        PrintMp(playerInfo);
        Console.WriteLine(\$"ref 없이 MP : {playerInfo.mp}");         // -20 (기존 객체 값만 수정됨)

        PrintMpRef(ref playerInfo);
        Console.WriteLine(\$"ref 적용 후mP ref : {playerInfo.mp}");   // -1000 (새 객체로 교체됨)
    }
}
```

## 🔥 트러블슈팅
### 1. 구조체(struct) 생성자 및 접근 제한자 컴파일 오류
- **문제**: `struct PlayerInfo` 선언 시 기본 생성자를 만들어야 한다는 컴파일 오류(CS8983)가 발생하고, 외부에서 필드에 접근할 때 보호 수준 오류가 발생했다.
- **원인**: C# 10 이상에서 `struct` 필드에 초기값(`= 0`)을 직접 대입하면 매개변수 없는 생성자(`public PlayerInfo() { }`)를 명시해야 하는 문법 규칙이 있으며, 접근 제한자를 생략하면 기본값이 `private`으로 설정되기 때문이다.
- **해결**: `struct` 필드의 불필요한 초기값 대입을 제거하고, 외부에서 접근할 변수 앞에 `public`을 붙여 해결했다.

### 2. `ref` 매개변수 선언 위치 오류
- **문제**: 함수 매개변수로 `PlayerInfo ref hp`처럼 작성했더니 컴파일 오류가 발생했다.
- **원인**: `ref`는 매개변수의 전달 방식을 지정하는 키워드이므로 반드시 타입(자료형) 앞에 위치해야 한다.
- **해결**: `ref PlayerInfo hp`로 키워드를 타입 앞에 배치하여 해결했다.

### 3. `Main` 함수 실행 불가 오류
- **문제**: `Main` 함수를 작성했으나 프로그램이 실행되지 않고 컴파일 오류가 발생했다.
- **원인**: `Main` 함수를 `class ref실습` 중괄호 `{ }` 바깥에 선언했기 때문이다. C#은 모든 메서드가 반드시 클래스나 구조체 내부에 속해야 하는 객체지향(클래스 기반) 언어이다.
- **해결**: `Main` 함수를 `class ref실습`의 중괄호 내부로 이동시켜 정상 실행을 확인했다.
