# 깃을 통한 프로젝트 관리

- 수업 내용 정리.
    1> 깃과 깃허브 
    -> 깃은 도구, 깃허브는 도구를 관리하는 포털
    2> 깃을 올리는 과정 설명.
    -> Remote or Local에서 올릴 수 있으며 퍼블리시를 하면 레파지토리가 만들어지고 이후 변경사항 커밋 후 푸시를 하면 최신화가 된다.
    3> 로컬과 리모트    /   이 사이에 파일의 흐름 이해했는가
    -> 로컬과 리모트는 자기자신 밖에 모르기 때문에 서로 연결하려면 푸시를 해서 동기화를 해주어야한다.

  [육하원칙]
- 누가 깃을 쓰는가?
-> 파일을 다른 곳에서 사용하고 싶거나 공유하고 싶은 사람(프로그래머, 회사, 개인)

- 언제
-> 작업을 공유해야하거나 다른 컴퓨터에서 쓰려고 하기 전, 혹은 파일을 클라우드에 최신화하여 저장하고싶을때

- 어디서
-> Remote or Local 둘 다에서 gitHub에서

- 무엇을
-> 작업을 공유해야하거나 다른 컴퓨터에서 쓰려고 하는 파일을

- 어떻게
-> Local : 저장소 지정 - 퍼블리시 - 커밋 및 푸시

- 왜 쓰는가?
-> gitHub를 사용하는 곳이라면 어디서나 파일을 실시간으로 공유할 수 있기때문에 편리하고
또한 대부분의 회사나 프로젝트를 하는 곳에서 gitHub를 쓰고 있기 때문이다.
