# 05. 이벤트 — 변화 알리기

## 발행자와 구독자 분리하기

점수가 바뀔 때 기록을 남기고 화면을 갱신해야 할 수 있습니다. 점수 클래스가 모든 후속 기능을 직접 호출하면 기능 추가에 따라 의존 관계가 늘어납니다. **이벤트는 발행자가 변화를 알리고 구독자가 자신의 처리를 등록**하는 구조입니다.

`event Action<int>`는 정수 하나를 전달하는 이벤트입니다. 외부에서는 일반적으로 `+=`로 구독하고 `-=`로 해제할 수 있지만, 필드 형태 이벤트의 호출이나 전체 대입은 선언한 형식 내부로 제한됩니다. 단순한 public 대리자 필드와 다른 점입니다.

## 실행 예제

```csharp
using System;

class Program
{
    static void Main()
    {
        ScoreBoard board = new ScoreBoard();
        board.Changed += PrintScore;
        board.Add(10);
        board.Changed -= PrintScore;
        board.Add(5);
        Console.WriteLine($"최종: {board.Score}");
    }

    static void PrintScore(int score) { Console.WriteLine($"변경: {score}"); }
}

class ScoreBoard
{
    public int Score { get; private set; }
    public event Action<int>? Changed;

    public void Add(int amount)
    {
        Score += amount;
        Changed?.Invoke(Score);
    }
}
```

```text
변경: 10
최종: 15
```

`?.Invoke`는 구독자가 없어 대리자가 null이면 호출을 생략합니다. 이 예제는 일반 C# 대리자에 대한 null 조건 접근입니다. `Action<int>?`의 Nullable 표기는 08단원에서 다룹니다.

## 구독의 수명 관리

발행자는 등록한 대리자를 통해 구독 대상이나 람다가 캡처한 객체를 계속 참조할 수 있습니다. 발행자가 더 오래 살아 있다면 사용이 끝난 구독을 해제해야 합니다. 같은 메서드를 두 번 등록하면 한 번 알림에 두 번 호출될 수 있습니다.

이벤트 호출은 기본적으로 동기적입니다. 구독 처리 중 예외가 발생하면 뒤의 구독자 호출까지 진행되지 않을 수 있으며 `event`가 자동으로 비동기화하거나 예외를 격리하지 않습니다.

## 실수 점검과 연습

- 구독과 해제를 짝으로 설계합니다. 해제할 대상을 다시 찾을 수 있도록 메서드나 대리자 변수를 유지하세요.
- 익명 람다를 다시 작성해 `-=`한다고 기존 구독이 해제된다고 가정하지 마세요.
- 구독자를 두 개 등록하고, 하나만 해제한 후 어떤 출력이 남는지 확인하세요.
