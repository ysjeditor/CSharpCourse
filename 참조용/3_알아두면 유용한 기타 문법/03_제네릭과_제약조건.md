# 03. 제네릭과 제약 조건

## 자료형만 다른 같은 기능 재사용하기

정수를 담는 상자와 문자열을 담는 상자를 각각 작성하면 보관·조회 코드는 거의 같아집니다. 모든 값을 `object`로 받는 방법도 있지만 꺼낼 때 형 변환이 필요하고 잘못된 변환은 실행 중 문제가 됩니다.

**제네릭은 사용할 자료형을 나중에 지정할 수 있는 정의**입니다. `Box<T>`에서 `T`는 형식 매개변수이고, `Box<int>`에서는 그 자리를 `int`로 사용합니다. 실행할 때마다 자료형이 마음대로 바뀌는 기능은 아닙니다.

## 제약 조건이 필요한 이유

제네릭 코드 안에서는 모든 `T`가 어떤 메서드를 가졌는지 알 수 없습니다. `where T : IMessage`로 제한하면 `T`는 해당 계약을 구현하므로 `Send`를 안전하게 호출할 수 있습니다. 제약 조건은 실제로 사용하는 연산을 설명해야 합니다.

| 제약 | 의미 |
| --- | --- |
| `where T : class` | 참조 형식 |
| `where T : struct` | Nullable이 아닌 값 형식 |
| `where T : IMessage` | 지정한 인터페이스 구현 |
| `where T : new()` | public 매개변수 없는 생성자를 가진 형식. 여러 제약 중 마지막에 작성 |

## 실행 예제

```csharp
using System;

class Program
{
    static void Main()
    {
        Box<int> number = new Box<int>(10);
        Console.WriteLine(number.Value);
        Deliver(new Notice());
    }

    static void Deliver<T>(T message) where T : IMessage
    {
        message.Send();
    }
}

class Box<T>
{
    public T Value { get; }
    public Box(T value) { Value = value; }
}

interface IMessage { void Send(); }
class Notice : IMessage
{
    public void Send() { Console.WriteLine("안내 전달"); }
}
```

```text
10
안내 전달
```

`Deliver`는 인수에서 `T`를 추론하므로 `Deliver<Notice>`를 생략할 수 있습니다. `Box<T>`는 클래스를 재사용하고, `Deliver<T>`는 메서드를 재사용한다는 차이도 확인하세요.

## 실수 점검과 연습

- 제약 없이 `new T()`를 호출할 수 없습니다. 생성이 필요하면 `new()` 제약 또는 생성 함수를 전달하는 방식을 검토합니다.
- `List<int>`와 `List<string>`은 다른 구성 형식입니다. 한 목록에 서로 다른 값을 자유롭게 넣을 수 있다는 뜻이 아닙니다.
- `Box<string>`을 만들고 값을 출력하세요. 이후 `IMessage`를 구현하지 않는 형식을 `Deliver`에 전달하면 언제 오류가 발생하는지 확인하세요.
