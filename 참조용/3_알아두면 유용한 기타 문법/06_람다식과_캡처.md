# 06. 람다식과 캡처

## 짧은 동작을 그 자리에서 표현하기

정렬 기준이나 숫자 검사처럼 한 곳에서 사용할 간단한 함수를 매번 별도 메서드로 만들면 코드를 오가며 읽어야 합니다. **람다식**은 매개변수와 실행 내용을 그 자리에서 표현하는 방법입니다. `value => value * 2`는 값을 받아 두 배를 결과로 만드는 함수 표현입니다.

람다식은 문맥에 따라 대리자나 식 트리로 변환됩니다. 여기서는 `Func`, `Action`에 연결하여 호출하는 용도로 사용합니다. 여러 문장이 필요하면 `value => { ...; return result; }`처럼 블록을 사용합니다.

## 캡처는 값의 순간 복사가 아닙니다

람다식이 바깥 지역 변수를 사용하면 해당 변수를 **캡처**할 수 있습니다. 아래 예제에서 `read`는 `bonus`를 생성 당시 숫자 10으로 고정해두지 않습니다. 호출 전 `bonus`가 20이 되었으므로 20을 읽습니다.

## 실행 예제

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        Func<int, int> twice = value => value * 2;
        Console.WriteLine(twice(3));
        int bonus = 10;
        Func<int> read = () => bonus;
        bonus = 20;
        Console.WriteLine(read());

        List<Action> actions = new List<Action>();
        for (int i = 0; i < 3; i++)
        {
            int copy = i;
            actions.Add(() => Console.WriteLine(copy));
        }
        foreach (Action action in actions) action();
    }
}
```

```text
6
20
0
1
2
```

`copy`는 각 반복의 블록에서 새로 선언됩니다. 람다식이 반복 제어 변수 `i`를 직접 사용하면 모든 호출이 반복 종료 후 같은 `i`를 읽어 3을 출력하는 결과가 될 수 있습니다.

## 실수 점검과 연습

- 캡처가 있는 람다식은 참조하는 상태의 수명을 늘리고 추가 할당을 유발할 수 있습니다. 호출 빈도가 높은 곳에서는 측정 후 판단합니다.
- 캡처가 필요 없다면 C# 9의 `static` 람다로 외부 지역 변수 사용을 막을 수 있습니다. 예: `static x => x * 2`.
- `copy`를 없애고 `i`를 직접 출력하도록 바꾼 후 실행 결과를 예상하세요.
- 처리 과정이 길어지면 의미 있는 이름의 메서드로 옮겨 읽기 쉽게 만드세요.
