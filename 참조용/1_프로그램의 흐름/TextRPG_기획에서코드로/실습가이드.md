# 두 문서를 읽고 프로젝트 구성하기

## 1. 빈 프로젝트 준비

별도 작업 폴더에서 `dotnet new console -n MyTextRpg --framework net10.0`으로 생성하거나 Visual Studio에서 .NET 10 콘솔 앱을 만듭니다. 학습용 프로젝트의 코드를 원본 템플릿에 덮어쓰지 않습니다.

아래 파일 경로를 준비합니다. 모든 형식의 네임스페이스는 `TextRpg`로 통일합니다. 폴더 이름이 자동으로 namespace를 일치시켜주지는 않으므로 직접 확인하세요.

```text
MyTextRpg/
  MyTextRpg.csproj
  Program.cs
  Game.cs
  Models/
    Job.cs
    Character.cs
    Monster.cs
  Systems/
    MonsterCodex.cs
    Guild.cs
    Battle.cs
```

Program은 `using TextRpg;` 후 `new Game().Run();`으로 연결합니다. 먼저 Game.Run에서 임시 시작 문장을 출력하고 종료하는 작은 프로그램을 빌드하세요. 나머지 파일의 완성 코드를 한꺼번에 복사하지 않습니다.

## 2. 기능마다 번역 기록 남기기

| 기획에서 읽은 문장 | 필요한 값 | 판단 조건 | 상태를 바꿀 메서드 | 확인 결과 |
| --- | --- | --- | --- | --- |
| 체력은 0 아래로 내려가지 않는다 | Hp, amount | 뺀 값이 0 미만인가 | TakeDamage | HP10, 피해20 → HP0 |
| 가입에는 레벨과 처치 수가 필요하다 | Level, Kills | 두 조건 모두 충족 | CanJoin은 판정만 | Lv2·1킬은 허용 |
| 처치한 몬스터는 반격하지 않는다 | Monster.IsAlive | 영웅 공격 직후 생존 | Fight에서 break | 한 방 처치 시 영웅 HP 유지 |

각 과제에서 같은 형식의 기록을 작성합니다. ‘무슨 파일을 만들었는가’뿐 아니라 ‘어떤 규칙을 어떤 메서드가 지키는가’를 적습니다.

## 3. 단계별 빌드

1. Job과 두 모델을 만들고 생성·Describe·TakeDamage를 확인합니다.
2. RollDamage를 만들고 확률 0/1을 직접 전달해 피해를 확인합니다.
3. 도감 배열과 Clone을 만들고 원본/사본의 HP를 비교합니다.
4. 전투를 연결하고 반환된 bool로 승패 후 처리를 나눕니다.
5. RecordKill과 전직을 연결하고 경계값을 확인합니다.
6. 길드 판정·등록·검색·추방을 독립적으로 확인합니다.
7. Game의 각 메뉴에 완성한 기능을 하나씩 연결합니다.
8. 두 문서 보기의 완료 체크를 자기 검증 후 표시합니다.

매 단계 `dotnet build` 후 `dotnet run` 또는 Visual Studio 디버깅으로 확인합니다. 출력을 늘리는 것만으로 상태가 올바르게 유지되는지 알 수 없으면 지역 변수·반환값·객체 참조를 디버거에서 확인합니다.

## 4. 최종 플레이 시나리오

- 이름을 아린으로 등록합니다. 초기 HP100, ATK15, 레벨1, 처치0을 확인합니다.
- 가입을 신청해 거절되는지 확인합니다.
- 슬라임을 두 번 처치하고 레벨2·처치2가 된 뒤 가입합니다.
- 슬라임을 두 번 더 처치해 레벨3·처치4·ATK21을 확인합니다.
- 기사 전직 후 최대 HP140·ATK26과 완전 회복을 확인합니다.
- 길드 검색에서 아린의 변경된 정보가 보이는지 확인합니다.
- 세라를 검색하고 도윤을 추방한 후 다시 검색합니다.
- 같은 이름 중복 신청, abc 사냥 번호, 0/5 사냥 번호를 확인합니다.
- 메뉴 0으로 종료합니다. 이 게임은 저장하지 않으므로 재실행 시 초기 상태입니다.

슬라임 4회 처치는 주어진 초기 능력치와 성장 회복으로 진행 가능한 시나리오입니다. 기본 치명타는 난수이므로 전투 출력의 턴 수 자체를 고정 정답으로 삼지 않습니다.

## 5. 설명으로 마무리

기획 문서 03단원의 ‘처치 후 반격 없음’을 실제 코드의 어느 조건과 break가 구현하는지 설명하세요. 길드 문서의 ‘가입 후 성장도 반영됨’이 같은 객체 참조와 어떻게 연결되는지 설명하세요. 마지막으로 HP 교환을 확장하려면 Character와 Monster의 형식 차이와 최대 HP 정책을 먼저 정하세요.
