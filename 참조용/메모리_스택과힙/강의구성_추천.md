# 메모리 강의 구성 제안

학생용 문서는 `index.html`이다. 이 문서는 수업 구성 검토를 위한 별도 자료이며 학생용 교재에서 연결하지 않는다.

## 권장 순서

1. 저장장치 → RAM → 프로세스·스레드 → CPU → 출력의 전체 흐름을 먼저 잡는다.
2. 호출이 끝나는 시점과 데이터가 필요 없어지는 시점이 다를 수 있음을 예제로 보여 준다.
3. 스택·힙을 수명 관리 규칙으로 이해한 다음 값·참조의 복사 규칙을 설명한다.
4. 참조 값 전달과 `ref`를 비교한다.
5. C++의 소유권·RAII와 C#의 GC·Dispose를 비교한다.
6. 정적·동적 타입은 별도의 비교 축임을 짧게 확인한다.
7. GC 루트 → 도달 가능성 → 회수·압축 → 세대의 순서로 원리를 확장한다.

## 넣기를 권장하는 내용

- **화면 출력과 파일 저장의 구분:** 변수 변경이 화면이나 저장 파일을 자동으로 바꾼다는 오해를 막는다.
- **객체와 변수의 상자 분리:** 변수 두 개와 객체 한 개를 그려 참조 공유를 설명한다.
- **값 타입 필드·배열·박싱의 반례:** ‘값 타입=스택’이라는 잘못된 규칙을 초기에 방지한다.
- **메서드 인수 전달:** 객체 수정과 변수 재대입의 차이는 실제 버그와 연결하기 좋다.
- **using/Dispose:** 메모리 회수와 파일·소켓 등 자원 반환의 책임을 구분한다.
- **불필요한 참조 유지:** GC가 있어도 정적 컬렉션이나 이벤트 연결로 메모리 사용이 계속 늘 수 있음을 설명한다.

이 항목들은 교재에 반영했다. 실행 추적은 실제 C# 실행기가 아니라 동작을 설명하는 학습 모형이다. 콘솔 실습은 별도로 실행한다.

## 줄이거나 뒤로 미루기를 권장하는 내용

- **정적·동적 타입 비교를 강의 도입에 길게 배치하지 않기:** 메모리 관리 방식과 인과관계가 있는 것처럼 받아들일 수 있다. 본문에서는 독립된 짧은 장으로 분리했다.
- **CPU 파이프라인·캐시 계층·GPU 렌더링 상세:** 전체 흐름을 파악하는 수준에 머물고 컴퓨터 구조 강의로 확장한다.
- **정확한 주소, 객체 헤더 크기, 세대별 임계값 암기:** 환경·구현 차이가 있으며 초급 학습 목표와 직접 연결되지 않는다.
- **쓰기 장벽:** 첫 수업에서는 ‘오래된 객체에서 새 객체로 향하는 연결도 기록한다’ 정도만 설명한다.
- **LOH, finalizer, 고정 객체:** 처음부터 본 흐름에 넣으면 부담이 크므로 접힌 심화 읽기로 제공했다.
- **GC.Collect 강제 호출 실험:** 즉시 삭제를 보장하는 사용법으로 오해하기 쉬워 기본 실습에서 제외했다.
- **비동기 상태 머신, 클로저, ref struct, stackalloc:** 기본 수명과 복사 규칙을 익힌 뒤 후속 강의에서 다룬다.

## 수업 시간 제안

| 회차 | 구성 | 시간 |
|---|---|---|
| 1회 | 실행 전체 흐름·프로세스 | 15분 |
| 1회 | 수명과 스택·힙 | 15분 |
| 1회 | 값·참조 복사와 단계별 모형 | 20분 |
| 2회 | 인수 전달·ref | 10분 |
| 2회 | C++·C# 비교와 정적·동적 타입 | 10분 |
| 2회 | GC 루트·회수·세대 | 20분 |
| 2회 | 출력 예측 실습·오개념 점검 | 10분 |

변수·메서드·클래스가 아직 익숙하지 않은 학생은 선수 문법과 실습 시간을 추가한다. 이 강의는 프로그래밍 문법을 전혀 배우지 않은 학생의 첫 수업보다는 기초 문법 이후의 메모리 입문에 적합하다.
