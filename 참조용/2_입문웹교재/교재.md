# C# 첫걸음

Visual Studio로 배우는 프로그래밍 입문 · 변수에서 클래스와 자료구조까지

## 01. Visual Studio와 첫 실행

### 학습 목표

프로젝트를 만들고 코드를 실행하며, 소스 코드와 실행 결과를 구분합니다.

### 개념 읽기

#### 코드를 쓰는 곳과 결과를 보는 곳

프로그램을 만든다는 것은 컴퓨터가 처리할 일을 순서대로 적고, 실행 결과가 의도와 같은지 확인하는 과정입니다. 우리가 적은 C# 코드를 **소스 코드**라고 합니다. Visual Studio는 코드를 편집하고 오류를 확인하며 실행할 수 있도록 도와주는 **통합 개발 환경(IDE)**입니다.

처음에는 글자를 입력받고 출력하는 **콘솔 앱**으로 연습합니다. 버튼이나 창 배치를 만들기 전에, 값이 어떻게 계산되고 실행 순서가 어떻게 달라지는지 집중해서 배울 수 있습니다.

#### 프로젝트 만들기

1. Visual Studio에서 새 프로젝트 만들기를 선택합니다.
2. C#의 **콘솔 앱**을 선택합니다. 이 교재의 웹 실행기와 맞추려면 현대적인 .NET 프로젝트를 사용합니다.
3. 프로젝트 이름을 `CSharpPractice`로 지정하고 생성합니다.
4. `Program.cs`의 내용을 아래 따라 하기 예제로 바꾸고 실행합니다.

| 이름 | 역할 | 비유 |
| --- | --- | --- |
| 솔루션 | 여러 프로젝트를 묶어 관리 | 프로젝트를 모아둔 서류철 |
| 프로젝트 | 코드와 실행 설정을 관리 | 프로그램 하나를 만들기 위한 작업 묶음 |
| `Program.cs` | C# 소스 코드를 적는 파일 | 컴퓨터가 처리할 지시문 |
| 콘솔 | 실행 중 입력과 출력을 주고받는 곳 | 프로그램과 대화하는 창 |

#### 한 문장씩 읽어보기

`Console.WriteLine("안녕하세요");`는 큰따옴표 안의 문자열을 출력하고 다음 줄로 이동합니다. `Console`은 콘솔 기능을 제공하는 형식이고, `WriteLine`은 그 기능 중 줄 단위로 출력하는 메서드입니다. 메서드의 자세한 구조는 뒤에서 배웁니다.

이 교재의 완성 예제는 **최상위 문** 방식으로 작성합니다. 실행 문장들을 파일 위쪽에 바로 적는 형식입니다. 기존 `Main` 메서드 안에 예제 전체를 다시 넣지 말고, **따라 하기 예제는 `Program.cs` 전체를 바꿔 실행**하세요. 개념 설명 중 짧은 코드 조각은 앞에서 선언한 변수가 필요할 수 있습니다.

> 소스 코드를 실행 가능한 형태로 바꾸는 과정을 **빌드**라고 합니다. 빌드에 실패했다면 현재 코드가 실행된 것이 아니므로, 오류를 먼저 읽고 수정합니다.

### 따라 하기

```csharp
using System;

Console.WriteLine("C# 공부를 시작합니다.");
Console.WriteLine("오늘의 목표: 직접 실행하기");
```

### 결과 확인

두 문장이 서로 다른 줄에 출력됩니다. 디버그 메뉴에서 디버깅 시작을 선택합니다. 기본 키 설정에서는 F5로 실행할 수 있습니다.

### 자주 하는 실수

Console과 console은 서로 다른 이름입니다. 문장 끝의 세미콜론과 문자열 양쪽의 큰따옴표를 확인하세요. 빌드에 실패했다면 이전 프로그램을 실행하지 말고 오류를 먼저 확인합니다.

### 직접 해보기

이름과 오늘 배우고 싶은 것을 각각 한 줄씩 출력하세요.

### 힌트와 해설

WriteLine을 두 번 호출합니다. 큰따옴표 안의 글자는 원하는 내용으로 바꿀 수 있습니다.

## 02. 변수와 기본 자료형

### 학습 목표

- 변수가 필요한 이유를 자신의 말로 설명합니다.
- **선언·초기화·대입**을 구분하고 직접 작성합니다.
- 저장할 값에 맞는 **기본 자료형**을 선택합니다.
- 변수의 값이 바뀌는 과정을 순서대로 따라갑니다.

### 개념 읽기

#### 데이터를 이름으로 보관하기 — 변수

게임에서 캐릭터가 피해를 받으면 체력이 줄어듭니다. 쇼핑 프로그램에서는 장바구니에 담은 수량에 따라 결제 금액이 달라집니다. 프로그램은 이처럼 **현재 값을 기억하고, 필요할 때 읽거나 바꿀 수 있어야** 합니다. 이때 사용하는 것이 **변수(Variable)**입니다.

처음에는 변수를 **이름표가 붙은 상자**로 생각해봅시다. 체력을 담는 상자에 `health`라는 이름을 붙여두면, 나중에 그 이름으로 체력을 확인하거나 변경할 수 있습니다. 이름이 없다면 여러 값 중 무엇이 체력인지 구별하기 어렵습니다.

상자에 어떤 종류의 물건을 넣을지 정하듯이, C#에서는 변수에 **어떤 종류의 값을 저장할지** 정합니다. 이것을 **자료형 또는 데이터 형식(Type)**이라고 합니다. 정수를 담는 `int`와 문자열을 다루는 `string`이 그 예입니다.

> 상자는 이해를 돕는 비유입니다. 자료형은 단순히 상자의 크기만 정하는 것이 아니라, 저장할 수 있는 값의 종류·범위와 가능한 연산을 정합니다. 문자열과 객체의 실제 저장 방식은 참조를 배우는 단원에서 다시 살펴봅니다.

#### 변수 선언 — 자료형과 이름 정하기

변수를 처음 만드는 일을 **선언(Declaration)**이라고 합니다. 자료형을 먼저 쓰고, 공백 뒤에 변수 이름을 적으며, 문장 끝에는 세미콜론 `;`을 붙입니다.

```csharp
int health;
```

| 코드의 부분 | 의미 |
| --- | --- |
| `int` | 정수를 저장하는 자료형 |
| `health` | 이 변수를 구별하기 위한 이름 |
| `;` | 이 문장이 끝났다는 표시 |

이 코드는 정수 값을 사용할 변수의 이름을 `health`로 정한 것입니다. **선언만 한 지역 변수는 아직 값을 읽을 수 없습니다.** 다음 단계에서 처음 사용할 값을 넣어야 합니다.

#### 초기화 — 처음 값 넣기

선언할 때 첫 값을 지정하는 것을 **초기화(Initialization)**라고 합니다. 다음 코드는 변수를 선언하면서 체력의 시작값을 100으로 지정합니다.

```csharp
int health = 100;
```

왼쪽의 `int health`는 변수를 선언하는 부분이고, 오른쪽의 `100`은 처음 넣을 값입니다. 중간의 `=`는 값을 저장하는 **대입 연산자**입니다. `100`처럼 코드에 직접 적은 값은 **리터럴(Literal)**이라고 부릅니다.

선언과 첫 대입을 나누어 작성할 수도 있습니다. 다음 두 문장을 순서대로 실행하면 위 예제와 같은 시작값을 갖게 됩니다.

```csharp
int health;       // 선언
health = 100;     // 첫 값 대입
```

> **지역 변수는 사용하기 전에 값이 확실히 대입되어야 합니다.** C#은 값이 대입되지 않은 지역 변수를 읽으면 컴파일 오류를 발생시킵니다. 알 수 없는 값을 읽도록 내버려두지 않습니다. 클래스의 필드나 배열 요소는 기본값을 받지만, 지금 작성하는 지역 변수와는 구분해야 합니다.

#### 대입 — 저장한 값 바꾸기

캐릭터가 피해를 받아 체력이 75가 되었다면, 이미 선언한 변수에 새 값을 넣습니다. 이때는 자료형을 다시 쓰지 않습니다.

```csharp
int health = 100;
health = 75;
Console.WriteLine(health);
```

실행 결과는 `75`입니다. 처음 값 100에 75를 추가한 것이 아니라, **기존 값을 새 값으로 바꾼 것**입니다. 같은 지역 변수 선언 공간에서 `int health`를 다시 선언하면 이름이 중복되어 오류가 발생합니다.

수학에서 `=`는 양쪽이 같다는 의미로 사용되지만, C#의 대입문은 **오른쪽을 먼저 계산하고 그 결과를 왼쪽 변수에 저장**합니다.

```csharp
int health = 100;
health = health - 25;
```

두 번째 문장은 다음 순서로 처리합니다.

1. 오른쪽의 `health`에서 현재 값 100을 읽습니다.
2. `100 - 25`를 계산하여 75를 구합니다.
3. 계산 결과 75를 왼쪽의 `health`에 저장합니다.

따라서 이 문장은 모순된 등식이 아니라 **현재 체력에서 25를 뺀 값으로 체력을 갱신하는 명령**입니다. 두 값이 같은지를 비교할 때 사용하는 `==`는 조건문 단원에서 배웁니다.

#### 기본 자료형 — 저장할 값의 종류 고르기

프로그램에 필요한 값이 모두 숫자는 아닙니다. 이름은 글자들의 묶음이고, 준비 완료 여부는 참이나 거짓으로 표현할 수 있습니다. 값의 목적에 맞는 자료형을 선택해야 의미 있는 계산과 판단을 할 수 있습니다.

| 자료형 | 저장하는 값 | 선언과 초기화 예시 | 사용 예 |
| --- | --- | --- | --- |
| `int` | 일정 범위의 정수 | `int count = 3;` | 인원, 개수, 점수 |
| `double` | 소수 부분을 표현하는 수 | `double speed = 2.5;` | 속도, 거리, 측정값 |
| `bool` | `true` 또는 `false` | `bool isReady = true;` | 준비 여부, 성공 여부 |
| `char` | UTF-16 코드 단위 하나 | `char grade = 'A';` | 영문 등급, 단일 기호 |
| `string` | 문자열 | `string name = "민수";` | 이름, 안내 문장 |

`int`에는 소수 부분을 그대로 저장할 수 없습니다. `double`은 소수 계산에 쓰지만 모든 십진 소수를 정확하게 표현하는 것은 아닙니다. 정밀한 금액 계산에 사용하는 `decimal` 같은 다른 자료형도 있으며, 여기서는 위의 다섯 가지에 먼저 익숙해집니다.

`bool` 값은 큰따옴표 없이 소문자로 `true`, `false`라고 작성합니다. `"true"`는 참이라는 논리값이 아니라 네 글자로 된 문자열입니다.

`char`는 작은따옴표 `'A'`, `string`은 큰따옴표 `"A"`를 사용합니다. 겉으로 보이는 글자가 같아도 자료형은 다릅니다. 특히 이모지처럼 `char` 하나로 표현되지 않는 문자도 있으므로, 이름이나 문장은 `string`으로 저장합니다.

#### 숫자와 숫자처럼 보이는 문자열

다음 두 값은 화면에 비슷하게 보이지만 프로그램에서는 다르게 취급합니다.

```csharp
int count = 10;
string label = "10";

Console.WriteLine(count + 5);
Console.WriteLine(label + "5");
```

```text
15
105
```

숫자끼리의 `+`는 덧셈을 하고, 문자열끼리의 `+`는 글자를 이어 붙입니다. 따라서 **겉모양이 아니라 자료형을 확인**해야 합니다. 문자열을 숫자로 바꾸는 방법은 다음 단원에서 배웁니다.

#### 변수 이름과 값 출력하기

변수 이름은 용도를 드러내도록 짓습니다. `a`보다 `health`, `b`보다 `studentCount`가 무엇을 저장하는지 설명하기 쉽습니다. 이 교재에서는 지역 변수 이름을 소문자로 시작하고 단어가 이어질 때 첫 글자를 대문자로 쓰는 방식을 사용합니다.

- `health`, `studentCount`, `isReady`는 사용할 수 있는 이름입니다.
- 숫자로 이름을 시작하거나 이름 중간에 공백을 넣을 수 없습니다.
- `int`처럼 문법에 쓰이는 예약어를 일반적인 변수 이름으로 사용하지 않습니다.
- 대문자와 소문자를 구별하므로 `health`와 `Health`는 다른 이름입니다.

변수의 값을 출력하려면 변수 이름을 큰따옴표로 감싸지 않습니다.

```csharp
int health = 75;
Console.WriteLine(health);     // 변수의 값인 75 출력
Console.WriteLine("health");   // health라는 글자 출력
```

변수 값을 문장 안에 넣고 싶다면 **문자열 보간**을 사용할 수 있습니다. 문자열 앞에 `$`를 붙이고, 값을 넣을 자리에 `{변수이름}`을 적습니다.

```csharp
Console.WriteLine($"현재 체력은 {health}입니다.");
```

이 코드는 앞에서 선언한 `health`가 있는 위치에서 이어서 실행하는 코드 조각입니다. 다음의 **따라 하기**는 `Program.cs` 전체를 바꿔 실행할 수 있는 완성 예제입니다.

### 따라 하기

```csharp
using System;

string name = "민수";
int level = 1;
double speed = 2.5;
bool isReady = true;
char grade = 'A';
level = level + 1;
Console.WriteLine($"{name}: 레벨 {level}, 속도 {speed}");
Console.WriteLine($"준비: {isReady}, 등급: {grade}");
```

### 결과 확인

```text
민수: 레벨 2, 속도 2.5
준비: True, 등급: A
```

`level`은 1로 시작하지만 `level = level + 1;`을 거쳐 2가 됩니다. `name`, `speed`, `isReady`, `grade`는 다시 대입하지 않았으므로 처음 값이 유지됩니다. 소수점 표시는 실행 환경의 문화권 설정에 따라 달라질 수 있습니다.

| 실행한 문장 | 실행 전 `level` | 실행 후 `level` |
| --- | --- | --- |
| `int level = 1;` | 선언 전 | 1 |
| `level = level + 1;` | 1 | 2 |
| `Console.WriteLine(...)` | 2 | 2 |

출력은 변수 값을 읽는 동작이므로 이 예제에서는 `level`의 값을 바꾸지 않습니다.

### 자주 하는 실수

| 잘못 작성한 예 | 문제가 생기는 이유 | 확인할 내용 |
| --- | --- | --- |
| `int level = "1";` | 정수 변수에 문자열을 넣었습니다. | 숫자 1에는 큰따옴표를 쓰지 않습니다. |
| `int health; Console.WriteLine(health);` | 지역 변수에 값을 대입하기 전에 읽었습니다. | 출력하기 전에 처음 값을 지정합니다. |
| `int health = 100; int health = 75;` | 같은 이름의 지역 변수를 중복 선언했습니다. | 두 번째 문장은 `health = 75;`로 대입합니다. |
| `char grade = "A";` | 문자열을 문자 변수에 넣었습니다. | 문자 하나는 `'A'`처럼 작은따옴표로 적습니다. |
| `Console.WriteLine("health");` | 오류는 없지만 변수 대신 글자를 출력합니다. | 변수 값을 원한다면 큰따옴표를 제거합니다. |

문제가 생겼을 때는 **자료형 → 변수 이름 → 오른쪽 값 → 기호**의 순서로 읽어보세요. 실행이 되는데 결과만 다르면 출력문에 큰따옴표가 붙었는지도 확인합니다.

### 직접 해보기

체력을 100으로 만들고 피해 25를 받은 뒤 남은 체력을 출력하세요. 화면에 `75`가 나오는지 아래 웹 실습창에서 채점할 수 있습니다.

추가로, 같은 변수에서 체력을 10 회복시키면 최종 값이 얼마인지 먼저 예상하고 Visual Studio 또는 직접 실행 기능으로 확인해보세요. 추가 실험을 채점할 때는 과제가 요구하는 출력과 다르다는 점에 주의합니다.

### 힌트와 해설

`int health = 100;`으로 선언과 초기화를 합니다. 이어서 `health = health - 25;`로 기존 값을 바꾸고 `Console.WriteLine(health);`로 출력합니다. 예상 결과는 75입니다. 이후 `health = health + 10;`을 추가하면 값은 85가 됩니다.

**스스로 설명하기:** 값을 다시 넣을 때 `int`를 반복해서 쓰지 않는 이유는 무엇일까요? 이미 선언한 변수를 새로 만드는 것이 아니라, 그 변수의 값을 변경하기 때문입니다.

## 03. 연산과 사용자 입력

### 학습 목표

연산 순서를 이해하고 문자열 입력을 숫자로 변환합니다.

### 개념 읽기

#### 연산자 — 저장한 값으로 계산하기

변수에 값을 저장했다면 계산에 사용할 수 있습니다. 가격과 수량을 곱해 총금액을 구할 때 사용하는 `*`처럼, 값에 어떤 처리를 할지 나타내는 기호를 **연산자**라고 합니다. 연산에 참여하는 값은 **피연산자**입니다. `price * 2`에서는 `price`와 `2`가 피연산자입니다.

| 연산자 | 하는 일 | 예 | 결과 |
| --- | --- | --- | --- |
| `+` | 덧셈 | `3 + 2` | `5` |
| `-` | 뺄셈 | `3 - 2` | `1` |
| `*` | 곱셈 | `3 * 2` | `6` |
| `/` | 나눗셈 | `5 / 2` | `2` |
| `%` | 나눈 나머지 | `5 % 2` | `1` |

곱셈과 나눗셈은 덧셈과 뺄셈보다 먼저 계산합니다. 따라서 `2 + 3 * 4`는 14이고, `(2 + 3) * 4`는 20입니다. 계산 순서가 헷갈린다면 괄호를 사용해 의도를 분명히 표현하세요.

#### 나눗셈의 결과는 자료형에 따라 달라집니다

정수끼리 나누면 결과도 정수이므로 소수 부분을 버리고 **0 방향으로 잘라냅니다**. `5 / 2`는 2입니다. 소수 부분이 필요하면 `5 / 2.0`처럼 적어도 한쪽을 실수로 계산해야 합니다. `double result = 5 / 2;`는 정수 계산이 먼저 끝나므로 결과를 2.5로 바꾸어주지 않습니다.

#### 입력은 먼저 문자열로 들어옵니다

키보드에서 1200을 입력해도 `Console.ReadLine()`이 돌려주는 값은 숫자가 아니라 문자열 `"1200"`입니다. 화면에서 숫자로 보여도 바로 정수 계산을 할 수 있는 것은 아닙니다. 입력 문자열을 필요한 숫자 자료형으로 바꾸는 **변환**이 필요합니다.

`int.TryParse`는 문자열을 정수로 바꾸어봅니다. 성공하면 `true`와 변환한 정수를 얻고, 실패하면 `false`를 얻습니다. 정수 범위를 벗어나거나 `abc`처럼 숫자가 아닌 입력도 실패합니다. 입력이 끝나 `ReadLine`이 `null`을 반환한 경우도 처리할 수 있습니다.

다음 예제에서 `out int price`는 변환 결과를 받을 변수를 선언합니다. `if`는 변환이 성공했을 때만 계산하도록 실행 경로를 고릅니다. 지금은 **입력 → 변환 성공 확인 → 계산**의 순서를 이해하고, 조건문의 자세한 문법은 다음 단원에서 배웁니다.

### 따라 하기

```csharp
using System;

Console.Write("가격을 입력하세요: ");
if (int.TryParse(Console.ReadLine(), out int price))
{
    Console.WriteLine($"2개 가격: {price * 2}");
}
else
{
    Console.WriteLine("정수로 입력해주세요.");
}
Console.WriteLine(5 / 2);
Console.WriteLine(5 / 2.0);
```

### 결과 확인

가격에 1200을 입력하면 2400이 출력됩니다. abc를 입력하면 안내 문장이 나옵니다. 마지막 두 줄은 각각 2와 2.5에 해당하는 값입니다. 소수점 표시는 실행 환경의 문화권 설정에 따라 다를 수 있습니다.

### 자주 하는 실수

문자열 "10" + "20"은 "1020"입니다. 숫자 덧셈을 하려면 먼저 숫자로 변환해야 합니다. TryParse가 실패했는데도 정상 입력처럼 계산하지 않도록 분기합니다.

### 직접 해보기

입력받은 분을 시간과 남은 분으로 바꾸세요. 135분은 2시간 15분입니다.

### 힌트와 해설

시간은 minutes / 60, 남은 분은 minutes % 60입니다. 음수 입력을 허용할지도 생각해보세요.

## 04. 조건문과 경계값

### 학습 목표

if, else if, else로 실행 경로를 선택하고 경계값을 검사합니다.

### 개념 읽기

#### 조건문 — 상황에 따라 다른 일을 하기

비가 오면 우산을 챙기고, 오지 않으면 그대로 나가는 것처럼 프로그램도 상황에 따라 다른 처리가 필요합니다. 점수가 기준 이상이면 합격을 출력하고, 그렇지 않으면 재도전을 안내하는 것이 한 예입니다. 이처럼 **조건을 검사해 실행할 코드를 선택하는 문장**을 조건문이라고 합니다.

`if` 뒤의 괄호에는 참 또는 거짓으로 판단할 수 있는 **조건식**을 적습니다. 조건식의 자료형은 `bool`이어야 합니다. 조건이 `true`이면 이어지는 중괄호 안의 코드 블록을 실행하고, `false`이면 건너뜁니다.

#### 비교 연산자로 질문 만들기

| 조건식 | 의미 |
| --- | --- |
| `score >= 60` | 점수가 60 이상인가? |
| `score < 60` | 점수가 60 미만인가? |
| `score == 60` | 점수가 정확히 60인가? |
| `score != 60` | 점수가 60과 다른가? |

`=`는 값을 넣는 대입이고 `==`는 같은지 묻는 비교입니다. 서로 역할이 다릅니다. 또한 `>`는 기준값을 포함하지 않고 `>=`는 포함합니다. 기준이 60일 때 59·60·61을 확인하는 이유가 바로 여기에 있습니다. 이런 경계 근처의 값을 **경계값**이라고 합니다.

#### 여러 조건과 실행 순서

두 조건을 함께 판단할 때는 **논리 연산자**를 사용합니다. `&&`는 양쪽 조건이 모두 참일 때, `||`는 하나 이상이 참일 때 참입니다. 예를 들어 `score < 0 || score > 100`은 점수가 허용 범위 밖에 있는지를 묻습니다.

`if`와 `else if`가 이어진 구조는 위에서 아래로 검사하고 **처음 참이 된 블록 하나만 실행**합니다. `else`는 앞의 조건이 모두 거짓일 때 실행하므로 별도의 조건식을 쓰지 않습니다. 각각 독립된 `if`를 여러 번 작성한 것과는 실행 방식이 다릅니다.

다음 예제는 먼저 잘못된 점수를 걸러내고, 유효한 점수에 대해서만 등급을 판단합니다. 처음에는 실행 본문이 한 줄이어도 중괄호를 작성해, 어느 문장이 어떤 조건에 속하는지 명확히 표시하세요.

### 따라 하기

```csharp
using System;

int score = 75;
if (score < 0 || score > 100)
{
    Console.WriteLine("점수 범위 오류");
}
else if (score >= 90)
{
    Console.WriteLine("A");
}
else if (score >= 60)
{
    Console.WriteLine("합격");
}
else
{
    Console.WriteLine("재도전");
}
```

### 결과 확인

75는 합격입니다. 값을 -1, 59, 60, 89, 90, 101로 바꿔 각 경로를 확인하세요.

### 자주 하는 실수

if (score >= 60);처럼 조건 뒤에 세미콜론을 붙이면 빈 문장이 본문이 됩니다. 다음 중괄호 블록이 조건과 무관하게 실행될 수 있습니다. 넓은 조건을 먼저 쓰면 뒤의 좁은 조건에 도달하지 못할 수도 있습니다.

### 직접 해보기

나이가 13 이상이고 19 이하이면 청소년이라고 출력하세요. 12, 13, 19, 20을 검사하세요.

### 힌트와 해설

age >= 13 && age <= 19를 사용합니다. 13과 19를 포함하려면 등호가 필요합니다.

## 05. switch와 메뉴 선택

### 학습 목표

정해진 선택지에 따라 서로 다른 기능을 실행합니다.

### 개념 읽기

#### 정해진 선택지를 처리하는 switch

프로그램 메뉴에서 1은 시작, 2는 도움말, 3은 종료라고 정했다면 입력값마다 할 일이 달라집니다. `if`를 이어 써도 되지만 **정해진 선택지와 처리 내용을 나란히 표현**할 때는 `switch`도 사용할 수 있습니다.

`switch (choice)`는 `choice`의 값을 기준으로 분기합니다. 다음 예제의 `case "1":`은 입력이 문자열 `"1"`인 경우 실행할 위치입니다. `default`는 어떤 `case`에도 해당하지 않을 때의 처리를 나타냅니다.

#### 선택된 분기가 실행되는 순서

1. `choice`에 입력 문자열을 저장합니다.
2. 일치하는 `case`가 있으면 그곳의 코드를 실행합니다.
3. `break`를 만나면 `switch`를 빠져나와 다음 코드로 진행합니다.

여기서 `break`는 프로그램 전체를 종료하는 명령이 아닙니다. 나중에 반복문 안에서 사용할 때도 **어느 구조를 빠져나오는지** 구분해야 합니다. C#은 일반적인 비어 있지 않은 `case`에서 다음 `case`로 암묵적으로 흘러가도록 허용하지 않으므로, 예제처럼 분기를 끝내는 문장을 작성합니다.

`Console.ReadLine() ?? ""`에서 `??`는 왼쪽이 `null`이면 오른쪽 값을 사용합니다. 이 예제는 입력이 더 없을 때 빈 문자열을 선택하여 `default`에서 처리하도록 합니다. 빈 문자열과 숫자 0은 서로 다른 값입니다.

### 따라 하기

```csharp
using System;

Console.Write("1: 시작 / 2: 도움말 > ");
string choice = Console.ReadLine() ?? "";
switch (choice)
{
    case "1":
        Console.WriteLine("시작합니다.");
        break;
    case "2":
        Console.WriteLine("번호를 입력해 선택하세요.");
        break;
    default:
        Console.WriteLine("없는 메뉴입니다.");
        break;
}
```

### 결과 확인

1, 2, 9를 각각 입력해보세요. ??는 왼쪽 값이 null이면 오른쪽 값을 사용합니다.

### 자주 하는 실수

문자열 "1"과 숫자 1은 다릅니다. switch 대상의 자료형에 맞는 case 값을 작성하세요.

### 직접 해보기

3을 입력하면 제작자 이름을 출력하는 메뉴를 추가하세요.

### 힌트와 해설

default 앞에 case "3": 블록을 추가하고 출력 후 break를 작성합니다.

## 06. while과 for 반복문

### 학습 목표

반복의 시작·유지·종료 조건을 설명합니다.

### 개념 읽기

#### 반복문 — 같은 처리를 여러 번 하기

학생 다섯 명의 점수를 더하거나 1부터 100까지 출력할 때, 비슷한 문장을 계속 복사하면 수정할 곳도 많아집니다. **반복문**은 같은 처리 과정을 조건에 따라 되풀이하는 구조입니다. 코드가 짧아지는 것뿐 아니라 처리 규칙을 한곳에서 관리할 수 있습니다.

#### while — 조건이 참인 동안

`while`은 본문을 실행하기 전에 조건을 검사합니다. 참이면 본문을 실행하고 다시 조건을 검사합니다. 처음부터 거짓이면 본문을 한 번도 실행하지 않습니다. 언제 끝날지보다 **어떤 상태인 동안 계속할지**가 중요할 때 사용합니다.

예를 들어 `count > 0`인 동안 출력하고 `count--`로 1을 줄이면, 언젠가 0이 되어 멈춥니다. `count--`를 빠뜨리면 조건이 계속 참이어서 **무한 반복**이 됩니다. 웹 실행기는 시간 제한으로 중단하며 Visual Studio에서는 디버깅 중지를 사용할 수 있습니다.

#### for — 반복 제어를 한곳에 모으기

`for (int i = 1; i <= 5; i++)`는 세 부분으로 읽습니다. `i++`는 이 예제에서 `i`의 값을 1 증가시킵니다.

| 부분 | 실행 시점 | 예제의 역할 |
| --- | --- | --- |
| `int i = 1` | 반복 시작 때 한 번 | 시작값 지정 |
| `i <= 5` | 매 회차 본문 실행 전 | 계속할지 검사 |
| `i++` | 본문 실행 후 | 다음 회차 준비 |

실행 순서는 **초기화 → 조건 → 본문 → 변경 → 다시 조건**입니다. `i <= 5`를 `i < 5`로 바꾸면 마지막 값 5를 처리하지 않습니다. 반복 횟수가 틀렸다면 처음 값과 마지막 값을 직접 적어보세요.

#### 누적값과 흐름 제어

합계처럼 이전 결과를 계속 이용하는 변수를 **누적 변수**라고 합니다. `sum += i`는 여기서 `sum = sum + i`와 같은 뜻입니다. `sum`을 반복문 밖에서 0으로 만들어야 이전 합계가 다음 반복에도 유지됩니다.

반복문 본문에서 `break`는 가장 가까운 반복을 끝내고, `continue`는 현재 회차의 남은 처리를 건너뜁니다. 특히 `while`에서 `continue`를 사용하면 값 변경 코드까지 건너뛰지 않는지 확인해야 합니다.

### 따라 하기

```csharp
using System;

int sum = 0;
for (int i = 1; i <= 5; i++)
{
    sum += i;
    Console.WriteLine($"i={i}, sum={sum}");
}

int count = 3;
while (count > 0)
{
    Console.WriteLine(count);
    count--;
}
```

### 결과 확인

합계는 1, 3, 6, 10, 15로 변합니다. while은 3, 2, 1을 출력합니다.

### 자주 하는 실수

sum을 반복문 안에서 0으로 만들면 누적되지 않습니다. i < 5와 i <= 5는 반복 횟수가 다릅니다. while에서 count--를 빠뜨리면 이 예제는 끝나지 않습니다.

### 직접 해보기

1부터 10까지 짝수만 출력하고 합계를 구하세요.

### 힌트와 해설

i % 2 == 0인 경우에만 출력과 합산을 수행합니다. 합계는 30입니다.

## 07. 배열과 데이터 순회

### 학습 목표

같은 종류의 여러 값을 배열에 저장하고 반복문으로 처리합니다.

### 개념 읽기

#### 여러 값을 하나의 이름으로 묶기

세 명의 점수를 `score1`, `score2`, `score3`으로 만들 수도 있지만, 학생이 100명이라면 변수도 100개가 필요해집니다. **배열(Array)**은 같은 자료형의 여러 값을 하나의 묶음으로 관리하고, 순서를 나타내는 번호로 각각 접근할 수 있게 합니다.

`int[] scores = { 70, 80, 90 };`에서 `int[]`는 정수 배열 자료형입니다. 중괄호 안의 값으로 요소 세 개를 가진 배열을 만들고, `scores`가 그 배열을 가리키도록 합니다. 배열 안의 각 값을 **요소**, 위치를 나타내는 번호를 **인덱스**라고 합니다.

| 접근 코드 | 의미 | 값 |
| --- | --- | --- |
| `scores[0]` | 첫 번째 요소 | 70 |
| `scores[1]` | 두 번째 요소 | 80 |
| `scores[2]` | 세 번째 요소 | 90 |
| `scores.Length` | 요소의 개수 | 3 |

#### 길이와 마지막 위치는 다릅니다

배열의 인덱스는 **0부터 시작**합니다. 따라서 길이가 3인 배열의 마지막 유효 인덱스는 2입니다. `scores[3]`은 네 번째 값을 요청하는 것이므로 범위 밖 접근입니다. `for`의 조건을 `i < scores.Length`로 작성하는 이유입니다.

배열은 만들어진 뒤 길이가 고정됩니다. 요소 값은 바꿀 수 있지만 그 배열 자체의 칸 수가 자동으로 늘어나지는 않습니다. `scores[1] = 100;`은 두 번째 요소를 변경하는 문장입니다. 개수가 자주 바뀌는 데이터에는 뒤에서 배울 `List<T>`를 고려합니다.

#### 순회와 평균 계산

모든 요소를 차례대로 처리하는 것을 **순회**라고 합니다. 인덱스가 필요하면 `for`, 각 값을 읽는 것이 목적이면 `foreach`를 사용할 수 있습니다. 다음 예제에서 `score`에는 매 회차의 점수가 들어오고, 합계에 더해집니다.

평균을 계산할 때 `(double)sum`으로 합계를 실수로 변환하면 정수 나눗셈으로 소수 부분을 잃지 않습니다. 또한 일반적인 프로그램에서는 배열이 비어 있을 때 어떻게 처리할지 먼저 정해야 합니다. 이 예제는 요소가 세 개 있으므로 바로 나눗셈을 합니다.

### 따라 하기

```csharp
using System;

int[] scores = { 70, 80, 90 };
int sum = 0;
foreach (int score in scores)
{
    sum += score;
}
double average = (double)sum / scores.Length;
Console.WriteLine($"평균: {average}");
for (int i = 0; i < scores.Length; i++)
{
    Console.WriteLine($"{i}번: {scores[i]}");
}
```

### 결과 확인

평균은 80입니다. 인덱스 0, 1, 2의 점수가 출력됩니다.

### 자주 하는 실수

scores[scores.Length]는 마지막 요소가 아니라 범위 밖 접근입니다. 배열이 비어 있을 때 평균 계산을 해도 되는지 별도로 판단해야 합니다.

### 직접 해보기

점수 배열에서 가장 큰 값을 찾아 출력하세요.

### 힌트와 해설

비어 있지 않은 배열에서 첫 요소를 max로 정합니다. 더 큰 값을 만날 때만 max를 바꿉니다. 이 예제의 답은 90입니다.

## 08. 메서드와 변수의 범위

### 학습 목표

기능을 메서드로 나누고 입력·결과·지역 변수의 범위를 구분합니다.

### 개념 읽기

#### 기능에 이름 붙이기

프로그램이 길어지면 입력, 계산, 출력이 뒤섞여 흐름을 파악하기 어려워집니다. 반복해서 쓰거나 하나의 역할로 묶을 수 있는 처리에 이름을 붙이면, **무엇을 하는 코드인지 이름을 통해 설명**할 수 있습니다. 클래스 안에서는 이런 작업 단위를 **메서드(Method)**로 정의합니다.

다음 예제의 `Add`는 최상위 문에 선언한 **지역 함수**입니다. 지금은 입력을 받고 결과를 돌려주는 원리를 익힌 뒤, 클래스 단원에서 메서드로 확장합니다.

#### 입력과 결과를 연결하기

`Add(10, 20)`처럼 함수 이름과 괄호를 쓰는 동작을 **호출**이라고 합니다. 호출할 때 전달하는 실제 값 10과 20은 **인수**이고, 함수 선언에서 그 값을 받는 `left`와 `right`는 **매개변수**입니다.

1. `Add(10, 20)`을 호출하면 실행이 함수 본문으로 이동합니다.
2. 매개변수 `left`와 `right`로 두 값을 사용합니다.
3. `return total;`이 계산 결과를 호출한 곳으로 돌려줍니다.
4. 돌려받은 값을 `result`에 저장한 뒤 다음 문장을 실행합니다.

함수 앞의 `int`는 **반환형**, 즉 결과로 돌려줄 값의 자료형입니다. 결과가 없는 작업은 `void`를 사용합니다. `Console.WriteLine`으로 화면에 보여주는 것과 `return`으로 호출한 코드에 값을 돌려주는 것은 다릅니다.

#### 변수를 사용할 수 있는 범위

함수 본문 안에서 만든 `total`은 그 블록 안에서만 사용할 수 있는 **지역 변수**입니다. 호출한 쪽에서는 `total`을 직접 읽는 대신 반환값을 받습니다. 이렇게 변수 이름을 사용할 수 있는 영역을 **범위(Scope)**라고 합니다.

예제의 `static`은 이 지역 함수가 바깥 지역 변수에 직접 의존하지 않도록 합니다. 필요한 값은 매개변수로 전달합니다. 지금은 메서드 문법을 외우기보다 **입력은 무엇이고 반환하는 결과는 무엇인지** 설명해보세요.

### 따라 하기

```csharp
using System;

int result = Add(10, 20);
Console.WriteLine(result);

static int Add(int left, int right)
{
    int total = left + right;
    return total;
}
```

### 결과 확인

30이 출력됩니다. 10과 20은 호출할 때 전달하는 인수이고 left와 right는 매개변수입니다.

### 자주 하는 실수

결과를 출력하는 것과 반환하는 것은 다릅니다. int를 반환한다고 선언했다면 필요한 실행 경로에서 int 값을 반환해야 합니다. total은 Add 밖에서 직접 사용할 수 없습니다.

### 직접 해보기

점수를 받아 60 이상이면 true를 반환하는 IsPassed 함수를 작성하세요.

### 힌트와 해설

static bool IsPassed(int score) { return score >= 60; }로 작성하고 59와 60을 전달해 확인합니다.

## 09. 클래스와 인스턴스

### 학습 목표

관련된 데이터와 기능을 묶고 각각 독립된 객체를 만듭니다.

### 개념 읽기

#### 관련된 값과 기능을 함께 관리하기

학생 정보를 이름 배열과 점수 배열로 따로 관리하면, 같은 위치의 값이 같은 학생인지 계속 확인해야 합니다. 학생 수가 늘거나 순서를 바꿀 때 이름과 점수의 연결이 틀어질 수도 있습니다. **학생 한 명의 이름과 점수, 그 정보를 설명하는 기능을 하나로 묶으면** 함께 관리하기 쉬워집니다.

**클래스(Class)**는 이렇게 객체가 가질 데이터와 동작을 정의하는 형식입니다. 아래의 `Student` 클래스는 이름과 점수를 저장하고 `Describe`로 자신을 설명하는 문자열을 만듭니다. 클래스를 설계도에 비유한다면, 그 설계대로 실제 생성한 대상이 **객체 또는 인스턴스(Instance)**입니다.

#### 클래스를 선언하는 것과 객체를 만드는 것

`class Student`는 어떤 학생 객체를 만들 수 있는지 정의합니다. 선언만으로 학생 한 명이 자동으로 생기는 것은 아닙니다. `new Student("지수", 80)`을 실행해야 이름과 점수를 가진 새 인스턴스가 만들어집니다.

`Student first`의 `Student`는 변수의 자료형입니다. 기본 자료형을 사용해 `int health`를 선언했던 것처럼, 이제는 직접 정의한 클래스를 자료형으로 사용할 수 있습니다.

| 구성 요소 | 예 | 역할 |
| --- | --- | --- |
| 클래스 | `Student` | 학생 객체의 형태와 기능 정의 |
| 생성자 | `Student(string name, int score)` | 새 객체에 처음 값을 설정 |
| 프로퍼티 | `Name`, `Score` | 객체의 값을 읽는 통로 |
| 메서드 | `Describe()` | 객체의 상태를 이용한 작업 |

#### 객체별 상태와 생성자

생성자는 클래스와 이름이 같고 반환형을 쓰지 않습니다. `new`로 객체를 생성할 때 호출되며, 전달받은 이름과 점수를 저장합니다. 예제의 `get;`만 있는 자동 프로퍼티는 이 생성자에서 초기화한 뒤 외부에서 다시 대입하지 못하도록 작성한 것입니다.

`first`와 `second`는 서로 따로 생성한 두 학생을 가리킵니다. 같은 클래스로 만들었어도 각 객체의 이름과 점수는 다를 수 있습니다. **클래스는 공통 정의이고 인스턴스는 개별 상태를 가진다**는 점을 기억하세요.

최상위 문 예제에서는 실행 코드를 먼저 쓰고 클래스 선언을 뒤에 둡니다. 클래스의 코드를 입력하기 전에, 학생 객체가 몇 개 생성되는지 먼저 예상해보세요.

### 따라 하기

```csharp
using System;

Student first = new Student("지수", 80);
Student second = new Student("현우", 95);
Console.WriteLine(first.Describe());
Console.WriteLine(second.Describe());

class Student
{
    public string Name { get; }
    public int Score { get; }

    public Student(string name, int score)
    {
        Name = name;
        Score = score;
    }

    public string Describe()
    {
        return $"{Name}: {Score}점";
    }
}
```

### 결과 확인

지수는 80점, 현우는 95점으로 각각 다른 상태를 가집니다.

### 자주 하는 실수

클래스를 선언하는 것만으로 객체가 생성되지는 않습니다. 인스턴스의 멤버를 사용하려면 먼저 객체를 만들고 그 객체를 통해 접근합니다.

### 직접 해보기

이름과 가격을 가진 Product 클래스를 만들고 상품 두 개를 출력하세요.

### 힌트와 해설

Student의 구조를 참고해 Name과 Price 프로퍼티, 생성자, 설명을 반환하는 메서드를 작성합니다.

## 10. 캡슐화와 참조

### 학습 목표

객체의 상태 변경을 제한하고 참조를 복사했을 때의 동작을 이해합니다.

### 개념 읽기

#### 객체의 상태를 보호해야 하는 이유

계좌 잔액을 아무 곳에서나 바꿀 수 있다면, 입금 기능에서 음수를 검사해도 다른 코드가 잔액을 음수로 만들 수 있습니다. 중요한 상태는 **허용한 동작을 통해서만 변경하도록** 설계해야 합니다. 데이터와 기능을 묶고 외부의 접근을 제한하는 것을 **캡슐화(Encapsulation)**라고 합니다.

아래의 `Balance { get; private set; }`은 외부에서는 잔액을 읽을 수 있지만 직접 바꿀 수 없도록 합니다. `public`은 외부에서도 사용할 수 있다는 뜻이고, 이 예제의 `private set`은 값 변경을 클래스 내부로 제한합니다. 외부 코드는 `Deposit`을 호출해 입금을 요청합니다.

#### 검증 후 상태 바꾸기

`Deposit`은 금액이 0 이하이면 `false`를 반환하고 끝냅니다. 유효한 금액일 때만 잔액을 변경하고 `true`를 반환합니다. **검증 → 상태 변경 → 성공 여부 반환**의 순서입니다. 반환한 성공 여부는 화면 안내나 다음 처리에 사용할 수 있습니다.

이 예제에서는 필드처럼 기본값을 받는 자동 프로퍼티의 저장 공간이 사용되어, 계좌의 시작 잔액이 0입니다. 앞에서 배운 ‘값을 대입하지 않은 지역 변수는 읽을 수 없다’는 규칙과 혼동하지 마세요.

#### 참조 복사와 객체 생성은 다릅니다

`Account shared = original;`은 새 계좌를 만들지 않습니다. `original`에 있던 **객체를 가리키는 참조**를 복사합니다. 두 변수는 같은 객체를 가리키므로 한쪽을 통해 입금하면 다른 쪽에서 읽는 잔액도 달라집니다.

| 코드 | 만들어지는 관계 |
| --- | --- |
| `Account shared = original;` | 두 변수가 같은 계좌를 가리킴 |
| `Account separate = new Account();` | 별도의 새 계좌를 생성함 |

`int` 같은 값 형식은 대입할 때 값 자체를 복사합니다. 클래스 같은 참조 형식은 참조를 복사합니다. 단, 객체 안에 값 형식 프로퍼티가 있다고 해서 그 객체를 대입할 때 객체 전체가 복제되는 것은 아닙니다.

객체 참조가 `null`이라는 것은 현재 가리키는 객체가 없다는 뜻입니다. 이 상태에서 멤버에 접근하면 예외가 발생하므로 먼저 존재 여부를 확인해야 합니다. 또한 `static` 멤버는 개별 인스턴스가 아니라 형식에 속하며, 계좌별 잔액처럼 각 객체가 따로 가져야 할 상태와 구분합니다.

### 따라 하기

```csharp
using System;

Account original = new Account();
Account shared = original;
shared.Deposit(100);
Console.WriteLine(original.Balance);
Console.WriteLine(original.Deposit(-10));

class Account
{
    public int Balance { get; private set; }

    public bool Deposit(int amount)
    {
        if (amount <= 0)
        {
            return false;
        }
        Balance += amount;
        return true;
    }
}
```

### 결과 확인

100과 False가 출력됩니다. 두 변수는 같은 계좌를 가리킵니다. 음수 입금은 거절됩니다.

### 자주 하는 실수

shared에 대입했다고 별도 계좌가 생기는 것은 아닙니다. 별도 계좌가 필요하면 new Account()로 새 객체를 만듭니다. static 멤버는 특정 인스턴스가 아니라 형식에 속한다는 점도 구분하세요.

### 직접 해보기

잔액보다 큰 금액과 0 이하 금액을 거절하는 Withdraw 메서드를 추가하세요.

### 힌트와 해설

amount <= 0 || amount > Balance이면 false를 반환합니다. 나머지 경우에만 잔액을 줄이고 true를 반환하세요.

## 11. List와 Dictionary

### 학습 목표

길이가 바뀌는 목록과 키로 검색하는 데이터 구조를 사용합니다.

### 개념 읽기

#### 개수가 바뀌는 데이터 — List

학생이 수업에 새로 등록하거나 탈퇴하면 명단의 크기도 달라집니다. 길이가 고정된 배열만으로 관리하려면 새 배열을 만들고 값을 옮기는 처리가 필요할 수 있습니다. **요소를 추가하거나 삭제하는 목록**을 다루기 위해 `List<T>`를 사용할 수 있습니다.

`T`는 실제로 저장할 자료형을 넣는 자리입니다. `List<string>`은 문자열 목록이고, `List<Student>`는 학생 객체를 담는 목록입니다. 이렇게 자료형을 지정해 재사용하는 방식을 **제네릭(Generics)**이라고 합니다. 지금은 꺾쇠괄호 안에서 어떤 자료형을 저장하는지 읽을 수 있으면 됩니다.

| 작업 | 코드 예 | 의미 |
| --- | --- | --- |
| 추가 | `names.Add("지수")` | 끝에 요소 추가 |
| 조회 | `names[0]` | 첫 번째 요소 읽기 |
| 수정 | `names[0] = "현우"` | 첫 번째 요소 변경 |
| 삭제 | `names.Remove("지수")` | 일치하는 첫 요소 삭제 시도 |
| 개수 확인 | `names.Count` | 현재 들어 있는 요소 수 |

List도 인덱스는 0부터 시작하며, 삭제하면 뒤의 요소 위치가 달라질 수 있습니다. 인덱스를 학생의 고유 번호처럼 사용하지 마세요.

#### 키로 찾는 데이터 — Dictionary

이름 목록에서 특정 학생을 찾으려면 여러 요소를 비교해야 할 수 있습니다. 반면 ‘101번 학생’처럼 **고유한 번호로 바로 값을 찾고 싶을 때**는 `Dictionary<TKey, TValue>`로 키와 값을 연결할 수 있습니다.

`Dictionary<int, string>`에서 키는 `int`, 값은 `string`입니다. `students.Add(101, "현우")`는 101이라는 키와 현우라는 값을 연결합니다. 101은 첫 번째 위치라는 뜻이 아닙니다. Dictionary의 키와 List의 인덱스는 역할이 다릅니다.

키는 중복될 수 없지만 서로 다른 키에 같은 값이 들어가는 것은 가능합니다. `TryGetValue`는 키가 있는지 알려주고, 있으면 `out` 변수로 해당 값을 전달합니다. 없는 키를 인덱서로 바로 읽는 것보다 존재 여부를 함께 처리하기 쉽습니다.

> 자료구조는 이름을 외우는 것보다 **데이터 개수가 바뀌는지, 순서가 중요한지, 무엇으로 검색하는지**를 기준으로 고르는 연습이 중요합니다.

### 따라 하기

```csharp
using System;
using System.Collections.Generic;

List<string> names = new List<string>();
names.Add("지수");
names.Add("현우");
names.Remove("지수");
Console.WriteLine($"인원: {names.Count}");

Dictionary<int, string> students = new Dictionary<int, string>();
students.Add(101, "현우");
if (students.TryGetValue(101, out string? name))
{
    Console.WriteLine(name);
}
```

### 결과 확인

인원은 1이며 101번 학생은 현우입니다. 컬렉션의 요소 수는 Count, 배열의 길이는 Length로 확인합니다.

### 자주 하는 실수

Dictionary.Add에 이미 있는 키를 넣으면 예외가 발생합니다. 없는 키를 인덱서로 바로 읽어도 예외가 발생합니다. TryAdd와 TryGetValue를 사용할 수 있습니다. foreach로 List를 순회하는 동안 해당 목록을 추가·삭제하지 마세요.

### 직접 해보기

학생 번호를 입력받아 이름을 찾고, 없는 번호면 안내하세요.

### 힌트와 해설

TryParse로 번호 변환을 확인한 다음 TryGetValue로 존재 여부를 확인합니다. 잘못된 숫자 입력과 없는 학생 번호를 각각 시험하세요.

## 12. Stack, Queue, HashSet

### 학습 목표

처리 순서와 중복 허용 여부에 따라 자료구조를 선택합니다.

### 개념 읽기

#### 데이터가 나오는 순서도 중요합니다

자료구조는 값을 저장하는 방법뿐 아니라 **어떤 순서로 꺼낼지, 중복을 허용할지**도 정합니다. 같은 세 명의 이름을 저장하더라도 대기 순서대로 부르는 것과 최근 등록부터 취소하는 것은 서로 다른 처리입니다.

#### Stack — 마지막에 넣은 것을 먼저 꺼내기

접시를 쌓아두면 맨 위에 올린 접시부터 꺼내게 됩니다. `Stack<T>`도 마지막으로 넣은 값을 먼저 꺼내는 **후입선출(LIFO)** 구조입니다. `Push`로 넣고 `Pop`으로 꺼내며, `Pop`으로 꺼낸 요소는 스택에서 제거됩니다. `Peek`는 제거하지 않고 다음 요소를 확인합니다.

실행 취소를 생각하면 최근 작업부터 되돌려야 합니다. 스택은 이런 이력을 관리하는 데 사용할 수 있지만, 실제 취소 기능에서는 작업 이름뿐 아니라 되돌리기에 필요한 정보도 저장해야 합니다.

#### Queue — 먼저 넣은 것을 먼저 꺼내기

매장 대기줄에서는 먼저 도착한 사람을 먼저 부릅니다. `Queue<T>`는 먼저 넣은 값을 먼저 꺼내는 **선입선출(FIFO)** 구조입니다. `Enqueue`로 뒤에 등록하고 `Dequeue`로 앞에서 꺼냅니다. 두 명을 지수, 현우 순으로 넣으면 지수가 먼저 나옵니다.

스택과 큐 모두 비어 있는 상태에서 일반적인 꺼내기 메서드를 호출하면 예외가 발생합니다. `Count`로 요소가 있는지 확인하거나, 성공 여부를 반환하는 `TryPop`과 `TryDequeue`를 사용할 수 있습니다.

#### HashSet — 중복 없이 저장하기

참가자 이름을 목록에 넣을 때 같은 이름을 여러 번 받아서는 안 되는 상황이라면 `HashSet<T>`를 사용할 수 있습니다. **이미 있는 값은 새로 추가하지 않는 집합**입니다. `Add`는 새로 추가하면 `true`, 같은 값이 이미 있으면 `false`를 반환합니다.

| 필요한 동작 | 선택할 수 있는 자료구조 | 핵심 기준 |
| --- | --- | --- |
| 최근 작업부터 꺼내기 | `Stack<T>` | 마지막 입력 우선 |
| 등록 순서대로 꺼내기 | `Queue<T>` | 처음 입력 우선 |
| 중복 참가 막기 | `HashSet<T>` | 값의 중복 여부 |

HashSet에 넣은 순서대로 항상 나올 것이라고 가정하지 않습니다. 또한 동명이인도 있을 수 있는 실제 시스템에서는 이름 대신 고유 번호를 중복 확인 기준으로 삼아야 합니다.

### 따라 하기

```csharp
using System;
using System.Collections.Generic;

Stack<string> history = new Stack<string>();
history.Push("첫 작업");
history.Push("두 번째 작업");
Console.WriteLine(history.Pop());

Queue<string> waiting = new Queue<string>();
waiting.Enqueue("지수");
waiting.Enqueue("현우");
Console.WriteLine(waiting.Dequeue());

HashSet<string> members = new HashSet<string>();
Console.WriteLine(members.Add("지수"));
Console.WriteLine(members.Add("지수"));
```

### 결과 확인

두 번째 작업, 지수, True, False 순서로 출력됩니다. 집합에 같은 값을 다시 추가하면 새 요소가 들어가지 않고 false가 반환됩니다.

### 자주 하는 실수

빈 스택의 Pop과 빈 큐의 Dequeue는 예외를 발생시킵니다. Count를 확인하거나 TryPop, TryDequeue를 사용하세요. HashSet의 열거 순서를 입력 순서라고 가정하지 않습니다.

### 직접 해보기

대기자 세 명을 등록하고 비어 있을 때까지 한 명씩 호출하세요.

### 힌트와 해설

while (waiting.Count > 0) 안에서 Dequeue를 호출합니다. 마지막에 빈 상태에서 다시 꺼내지 않는지 확인하세요.

## 13. 오류를 스스로 찾는 순서

### 학습 목표

문제의 증거를 모으고 한 번에 한 가지 가설을 검증합니다.

### 개념 읽기

#### 오류를 분류하면 첫 행동이 달라집니다

코드가 안 된다는 말만으로는 어디서부터 확인해야 할지 알기 어렵습니다. 먼저 **실행 전부터 막혔는지, 실행 중에 멈췄는지, 끝났지만 결과가 다른지**를 구분하세요. 이것만으로 확인할 도구와 위치를 좁힐 수 있습니다.

| 종류 | 보이는 현상 | 먼저 확인할 것 |
| --- | --- | --- |
| 컴파일·빌드 오류 | 현재 코드를 실행할 수 없음 | 오류 메시지, 자료형, 이름, 기호 |
| 실행 중 예외 | 실행 도중 특정 연산에 실패 | 예외 이름, 해당 줄, 변수 값 |
| 논리 오류 | 실행되지만 의도와 다른 결과 | 예상값과 실제값이 처음 달라진 시점 |

오류 목록에서 항목을 두 번 클릭하면 해당 코드로 이동할 수 있습니다. 다만 표시된 줄이 항상 원인이 시작된 위치는 아닙니다. 앞줄에서 큰따옴표나 괄호를 빠뜨렸다면 다음 줄에서 오류가 발견될 수도 있습니다. 한 원인 때문에 오류가 여러 개 나타나는 경우도 있습니다.

#### 중단점으로 실행을 잠시 멈추기

**중단점**은 코드를 지우거나 출력문을 추가하지 않고 특정 위치에서 실행을 잠시 멈추게 합니다. Visual Studio의 코드 왼쪽 여백에 중단점을 설정하고 디버깅을 시작하세요. 멈춘 상태에서는 변수에 마우스를 올리거나 지역 변수 창으로 현재 값을 확인할 수 있습니다.

한 단계씩 코드 실행을 선택하면 한 문장 단위로 변화를 관찰할 수 있습니다. 기본 키 설정에서는 `F10`입니다. 강조된 줄은 보통 **다음에 실행할 문장**이므로, 아직 그 줄의 계산 결과가 반영되지 않았을 수 있습니다.

#### 수정 전에 가설 세우기

1. 같은 입력에 대해 나와야 할 결과를 적습니다.
2. 실제 출력 또는 오류 메시지를 그대로 확인합니다.
3. 처음 다르게 동작한 줄과 그때의 변수 값을 찾습니다.
4. 이유를 한 가지 예상하고, 한 번에 한 부분만 바꿉니다.
5. 같은 입력으로 재확인하고 경계값도 시험합니다.

다음 합계 예제에서는 반복할 때마다 `i`와 `sum`이 얼마가 될지 먼저 적어보세요. 단순히 정답 210만 확인하는 것보다 **값이 바뀌는 과정을 설명하는 연습**이 오류를 찾는 데 도움이 됩니다.

### 따라 하기

```csharp
using System;

int[] scores = { 60, 70, 80 };
int sum = 0;
for (int i = 0; i < scores.Length; i++)
{
    sum += scores[i];
}
Console.WriteLine(sum);
```

### 결과 확인

sum += scores[i];에 중단점을 놓습니다. 각 반복에서 i와 sum을 확인하세요. 합계는 210입니다.

### 자주 하는 실수

오류가 여러 개라고 여러 줄을 동시에 바꾸지 마세요. 위쪽 코드의 원인 하나를 고치고 다시 빌드합니다. 경고와 오류는 다르지만 경고도 원인을 읽고 판단해야 합니다.

### 직접 해보기

조건을 i <= scores.Length로 바꾸고 실행해보세요. 어느 i에서 어떤 문제가 생기는지 기록한 다음 복구하세요.

### 힌트와 해설

i가 3일 때 유효 인덱스 범위를 벗어납니다. 도움을 요청할 때 예상 결과, 실제 결과, 오류 메시지, 해본 수정을 함께 전달하세요.

## 14. 종합 실습: 학생 관리 프로그램

### 학습 목표

클래스와 컬렉션, 메서드, 입력 검증을 결합합니다.

### 개념 읽기

#### 배운 문법을 하나의 프로그램으로 연결하기

변수는 값을 기억하고, 조건문은 판단하고, 반복문은 같은 일을 되풀이합니다. 메서드는 기능을 나누며, 클래스는 관련 상태와 동작을 묶습니다. 최종 과제에서는 이 개념들을 **학생 관리**라는 하나의 목적에 연결합니다.

완성할 프로그램은 학생 등록, 목록 보기, 번호 검색, 종료 기능을 가집니다. 처음부터 메뉴 전체를 만들기보다, 학생 두 명을 저장하고 출력하는 아래 예제를 먼저 실행하세요. 한 기능씩 추가하면 문제가 생겼을 때 어느 변경을 확인할지도 분명해집니다.

#### 데이터와 기능을 먼저 정하기

| 결정할 것 | 이 과제의 선택 | 이유 |
| --- | --- | --- |
| 학생 한 명의 데이터 | 이름과 점수를 가진 `Student` | 관련 정보를 묶어서 관리 |
| 학생 구분 방법 | 고유한 학생 번호 | 이름이 같아도 구별 가능 |
| 저장 구조 | `Dictionary<int, Student>` | 번호로 학생 객체 검색 |
| 입력 검증 | 숫자 변환, 빈 이름, 점수 범위 검사 | 잘못된 데이터 등록 방지 |

번호는 Dictionary의 키로 두고, 값에는 학생 객체를 저장합니다. 학생 정보를 읽으려면 먼저 번호로 객체를 찾고, 그 객체의 `Name`이나 `Score`를 읽습니다. `entry.Key`는 학생 번호이고 `entry.Value`는 학생 객체입니다.

#### 기능을 추가하는 순서

1. 고정된 학생 두 명을 저장하고 목록을 출력합니다.
2. 입력받은 번호로 학생을 검색하고 없는 번호를 처리합니다.
3. 새 학생의 입력을 검증하고 중복 번호를 거절합니다.
4. 메뉴를 반복하고 사용자가 종료를 선택하면 끝냅니다.
5. 등록·목록·검색을 메서드로 나누고 기존 동작을 다시 확인합니다.

**잘못된 입력은 등록 전에 거절**해야 합니다. 입력 검증에 실패했는데 객체를 먼저 추가하면 저장한 상태를 다시 되돌려야 하기 때문입니다. 아래 웹 실습은 이 중 ‘등록 검증’ 기능을 여러 입력으로 검사합니다. 전체 메뉴 프로그램은 Visual Studio에서 확장하는 종합 과제입니다.

### 따라 하기

```csharp
using System;
using System.Collections.Generic;

Dictionary<int, Student> students = new Dictionary<int, Student>();
students.Add(101, new Student("지수", 80));
students.Add(102, new Student("현우", 95));
foreach (var entry in students)
{
    Console.WriteLine($"{entry.Key}: {entry.Value.Name} / {entry.Value.Score}점");
}

class Student
{
    public string Name { get; }
    public int Score { get; }
    public Student(string name, int score)
    {
        Name = name;
        Score = score;
    }
}
```

### 결과 확인

101번과 102번 학생의 이름과 점수가 출력됩니다. 출력 순서 자체를 기능의 조건으로 삼지 마세요.

### 자주 하는 실수

한 기능을 추가할 때마다 기존 기능도 다시 확인합니다. 등록 전에는 번호 중복, 빈 이름, 점수 범위, 숫자 변환 실패를 검사하세요. 잘못된 입력을 조용히 0점으로 처리하지 않습니다.

### 직접 해보기

1: 등록, 2: 목록, 3: 검색, 0: 종료 메뉴를 반복하세요. 기능을 메서드로 나누고 정상 등록, 중복 번호, 없는 번호, 문자 점수, -1점, 101점을 확인하세요.

### 힌트와 해설

while로 메뉴를 반복하고 switch로 분기합니다. 입력은 TryParse, 중복은 ContainsKey 또는 TryAdd, 검색은 TryGetValue로 확인합니다. 완성 기준은 정상 동작뿐 아니라 잘못된 입력 후에도 다음 메뉴를 사용할 수 있는 것입니다.
